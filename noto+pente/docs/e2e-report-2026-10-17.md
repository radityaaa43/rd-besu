## Findings

**F1 (fixed, 4018dd6).** `bond/src/abis/BondTracker.json` and `BondTrackerPublic.json` were the upstream v1.0.0 artifacts, so a series issued by `npm run start` did not carry fixes #1 or #2 and `npm run reconcile` could not read `lockedBalanceOf` (R3 shows `locked=n/a` on S1). The example now deploys the platform's tracker pair. Found because R3 printed `n/a`.

**F2 (no change needed; the backend path was removed from the repo later the same day, user decision 2026-10-17).** The platform client (`common/paladin-client`, since deleted) already settles the primary flow and outright through Agreement + RestrictedAtom (its D1 comment, `client.ts` ~L2734). Only the example CLI (`bond/src/index.ts`) and `swap-noto` were still on upstream Atom, which Phase 1 fixed.

**F3 (observation).** The status-only public tracker works as designed live: STARTED while units remain (P3), COMPLETE as soon as the private counter reaches zero (P4), with no amount in any call or event field.

**F4 (observation, test timing).** The private BondTracker is updated by Noto's hook after the base-ledger transaction, so right after a cancel receipt `lockedBalanceOf(custodian)` still read 10 for a few seconds before dropping to 0 (reconcile a minute later showed locked 0, delta 0). The first run of `live-cancel-issuance.ts` read it once, immediately, and failed that one check in both cases (KA5 and KB5 equivalents) on atoms `0xf30783a8254ea812191c2547c215950d0dbe8e7c` (cancel `0x1df652619a41e50c935d7d4a155a3ca4162c526a5fadba60d17abb75c5e1e80c`) and `0x0e1e3ecdcddd0a955c752b022249e3aa8cbe0a72` (cancel `0xec9b4f1b22edd73f7f44507bf7a88e0136f2fa210e6b707713bfeecc310f6a6a`); every contract and balance check in that run passed. The script now polls the tracker until it settles, and the table above is from the second run. No contract or cluster issue.

## Not covered

- The Agreement-based primary flow in `paladin-client` (backend path): out of scope (user decision 2026-10-17: same scope as stealth/zeto, script-level only). Not driven live and not planned.
- BI-offline behaviour (all noto flows need the node1 notary) was not exercised here.
- N6 needed a second attempt: the first run on S1 stopped on a bug in the test script itself (it read Noto lock owners without the `0x` prefix and did not expect `ptx_sendTransaction` to throw on a reverting call). The atom was left Pending with both legs delegated, the script was fixed, and the second run resumed on that same atom with `--atom` and passed. No contract or cluster issue.
- Cancel of a pending issuance atom and a pending swap atom, which this section used to list as not covered, is now covered live (KA1..KR1, SA1..SB6 above).
- Stranger cancel is shown by the `NotAParty` revert text, not a transaction hash (see note under the table title).
